# Локальный context gateway с отдельными способами получения данных

Развиваем TGSUM в локальный шлюз подготовки контекста из нескольких мессенджеров.
Единицей поддержки становится **платформа + способ получения данных**:
archive importer, user OAuth, bot или local data connector. Каждому способу
нужны собственные доказательства возможностей и условий использования.
Это позволяет сохранить локальный Telegram parser и добавлять источники без
общей пользовательской сессии на все мессенджеры.

Принято направление и границы реализации; новые функции ещё не выпущены.
Текущее поведение v0.2 описывает [прежняя спецификация](../specs/tgsum.md),
следующий контракт — [спецификация gateway](../specs/context-gateway.md).
Граница ответственности и приоритет способов подключения уточнены в
[ADR-0002](0002-user-controlled-content.md).

## Решения

- Локальный `source → scope → normalize → sanitize → bundle` остаётся
  самостоятельным продуктовым потоком. Запуск AI добавляется отдельным действием.
- Получение архива, его импорт и запуск анализа имеют отдельные разрешения,
  состояния и ошибки. Watcher готового экспорта не называется live sync.
- Registry хранит отдельно выбранный scope и полномочия credential,
  возможности API, ограничения использования и степень проверки.
- Telegram Desktop export остаётся текущим источником. Следующая работа —
  поддержка одиночного экспорта и безопасный повторный импорт.
- Автоматизация неизменённого Telegram Desktop в изолированной среде допускается
  как исследовательский прототип с явным запуском пользователем. Production
  решение принимается после проверки стабильности и условий конкретного сценария.
- Форк Telegram Desktop и прямой MTProto/TDLib не входят в ближайший выпуск:
  они добавляют поддержку клиента и полномочную сессию. Прямой API остаётся
  advanced/research вариантом, оцениваемым по пользе и ограничениям платформы.
- Обработка локального файла не является доказательством разрешения на его
  передачу облачному AI. Sanitizer уменьшает раскрытие данных, но не выдаёт права.
- Поддержка и выпуск каждого connector проходят
  [обязательный внутренний review](../connectors/review-policy.md).

## Последствия и альтернативы

Единый «логин пользователя → история» проще демонстрировать, но смешивает
различные правила платформ и полномочия. Отдельные способы подключения требуют
больше проверок, зато позволяют явно показывать пользователю реальный доступ.

Собственный форк официального клиента даёт контроль над exporter, но связывает
продукт с обновлениями клиента, лицензией, авторизацией и API. Внешний помощник
над неизменённым клиентом оставляем отдельным экспериментом; оснований считать
его надёжным headless API пока нет.

Основания: [Telegram](../research/telegram-export-automation.md),
[остальные платформы](../research/connector-support-2026-09-26.md).
