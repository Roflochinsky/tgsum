# Пользователь управляет содержимым; TGSUM отвечает за интеграцию

TGSUM готовит локальный контекст из явно подключённых источников. Пользователь
и его организация решают, какие переписки анализировать и как использовать
содержимое. TGSUM отвечает за способ подключения, минимизацию сохраняемых
данных, надёжность обработки и понятное действие передачи выбранному агенту.

Платформенные условия остаются частью внутреннего engineering/release review:
они влияют на выбор и поддержку интеграции. Это не проверка прав пользователя
при каждом импорте или анализе. Эта граница уточняет
[ADR-0001](0001-local-context-gateway.md).

## Ответственность и UX

| Зона | Принцип |
| --- | --- |
| Выбор переписки и допустимость использования | Пользователь / его организация |
| Выбор AI и дальнейшее использование результата | Пользователь |
| Preprocessing | Локально; сообщения не собираются на сервер TGSUM |
| Project storage | Только выбранные обсуждения и файлы; полный исходный архив по умолчанию не копируется |
| Передача агенту | Показать scope, получателя, coverage и preview; явный Run |
| Автоматический refresh | Отдельная настройка пользователя, Stop/Disconnect, понятные ошибки |
| Credentials официального клиента | Остаются у клиента; Bridge не читает session DB/tdata/cookies |
| Credentials API | Только специально выданные TGSUM OAuth/bot tokens; минимальные полномочия, явное управление хранением/отзывом |

В UX нет требования собирать доказательства согласия каждого участника,
юридической анкеты или автоматического запрета анализа по классификации прав
на переписку. Поле `ai_policy` в registry — исследовательская заметка для
разработчика, не вердикт о правах пользователя и не runtime разрешение на Run.
Зафиксированные ограничения платформ не скрываются и не объявляются снятыми
одним решением пользователя: способ, который продукт не может поддерживать,
не выпускается под видом надёжной официальной интеграции.

## Предпочтение способов получения

1. Надёжный Official Client Bridge над официальным export/backup.
2. Предоставленный пользователем официальный архив — постоянный fallback.
3. Официальный API с минимальными достаточными полномочиями, если архив
   уступает по полноте или UX (например, бизнес-сценарий Teams/Google Chat).
4. Официальный бот в выбранных рабочих обсуждениях, если так устроена платформа.
5. Прямой user API/session как advanced experiment при подтверждённой пользе
   и приемлемых ограничениях. Не является общим механизмом всех коннекторов.

Bridge становится preferred только после проверенного PoC на поддерживаемой
версии клиента/ОС. Сейчас Telegram имеет manual export fallback; автоматический
Bridge ещё не реализован. Для интерфейса используем `Connect conversation`,
`Refresh source`, `Update project`, `Official client`, `Local archive`.

## Точные границы обещаний

Выбор чата приложением может быть уже прав токена. UI показывает реальную
границу, а реализация ограничивает запросы и сохранение выбранным scope.
Если пользователь дал полный архив, TGSUM читает его потоково для выбора;
гарантия минимизации относится к project storage и context bundle. После
одноразового bootstrap можно забыть исходный путь по выбору пользователя.

У Bridge нет messenger credentials, но у API-коннектора есть выданный токен,
а у Signal importer может быть локально предоставленный recovery key. Эти
значения не извлекаются из чужого/существующего профиля и не входят в bundle,
логи или результаты; сохранение для повторных запусков — отдельная настройка
через защищённое хранилище ОС. Формулировка «никогда не хранит никаких credentials»
не подходит ко всему продукту.
