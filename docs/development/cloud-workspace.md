# GitHub Actions → Codex по подписке → Notion

Работа `tgsum-plb`. Код: [worker](../../cloud/pipeline.py),
[workflow для закрытого репозитория](../../cloud/workflow.yml),
[пример настроек](../../cloud/config.example.json).
Это отдельный способ передачи, который не включается для старых проектов.
Реальная квалификация и состояние подключения фиксируются в Beads;
наличие кода или секретов не означает, что pipeline уже проверен на аккаунте.

## Управление

В карточке пакета сохраните выбор чатов/тем/периода и правила приватности,
укажите **приватный** GitHub и включите «Передавать выбранные сообщения…».
Нажмите «Сохранить настройки», затем «Собрать пакет». Автообновление пакета
проверяет сохранённую историю раз в 30 секунд, пока TGSUM запущен.
Остановка пакета останавливает будущую публикацию; уже переданные записи
могут ожидать обработки в GitHub. Чтобы остановить облачный worker, установите
`enabled: false` в `.tgsum/config.json` репозитория данных.

Папка GitHub: `packages/<project-id>/messages.jsonl` и `coverage.json` рядом
с готовым Markdown/вложениями. JSONL объединяет выбранные чаты; `source`
разделяет их устойчивым opaque ID. `evidence.id` сохраняется при правке,
`evidence.revision` меняется. `topic` — opaque ключ известной темы;
`null` и `topic_known: false` означают, что тема не определена.
Исходные native IDs, обратный индекс, пути и сырые логи не передаются.
Privacy работает тем же обработчиком, что и Markdown. Настройка картинок
по-прежнему означает передачу их оригиналов, включая метаданные.

`coverage.json` отмечает полноту, число пропусков, статистику фильтров и
подписанный локальным ключом fingerprint выбора/privacy. Сам fingerprint
не раскрывает внутренние значения. Логи не доказывают полную историю или
принятие каждого сообщения клиентом; отсутствие не считается удалением.

## Закрытый облачный runner

Копируются только доверенные `cloud/pipeline.py` → `.tgsum/pipeline.py` и
`cloud/workflow.yml` → `.github/workflows/telegram-workspace.yml` в частный
репозиторий данных. Настройки/личные Notion IDs хранятся там, не в публичном TGSUM.
`oauth_account_sha256` — SHA256 JSON-кодирования account_id **отдельной**
automation-сессии. Default — один анализ не чаще часа, timeout 5 минут,
ограниченный batch/context, без скрытого усечения большого сообщения.
`automatic: false` оставляет только manual qualification; для автоматики
после проверки включается `automatic: true`.

Секреты: `CODEX_AUTH_JSON`, `CODEX_AUTH_WRITER_TOKEN`, `NOTION_TOKEN`.
Writer — fine-grained PAT только к этому repo, Secrets read/write.
Сессия создаётся отдельным пользовательским входом ChatGPT, не копируется
из основной рабочей сессии. API-ключ, платный fallback и покупка кредитов
отсутствуют. Codex 0.155.1 выполняет собственный refresh; обновлённый cache
записывается через stdin `gh secret set` в finally, также после ошибки анализа.

Одна workflow concurrency на сессию. Repository secrets читаются GitHub
при постановке в очередь: если secret обновился не раньше `created_at` run,
этот job пропускает inference и ждёт нового workflow run. Rerun старого run
не заменяет новый dispatch. Ручная смена secret во время job блокирует writeback.
После revoke/истечения/потери обновлённого cache требуется новый отдельный login
и seed; автоматическое восстановление без действующей сессии не обещается.
Quota/таймаут не продвигает input checkpoint; следующий разрешённый запуск
может повторить анализ. Ответ, сохранённый в results, повторно не запрашивается.

Workflow выполняется только с default branch частного repo, не по PR.
CLI получает изолированный HOME/CODEX_HOME и окружение без GitHub/Notion keys,
игнорирует user config/rules; tools отключены для закреплённой версии.
Доверенные исходники worker не импортируются из сообщений. Вывод CLI и
тела HTTP-ошибок не печатаются; auth нет в git, artifacts или prompt.
Выбранная публикация сохраняется в истории Git, автоматической очистки нет.

## Результаты и повтор

`results/<project-id>/<run-key>.json` — проверенный ответ с задачами/отчётами.
`state/<project-id>.json` — analysis range/checkpoint, задачи и sync receipts.
Обрабатываются все промежуточные revisions после checkpoint, не только
последний push diff. Диапазон закрепляется до inference и читается кусками.
Новый выбор/privacy отменяет старый недоконченный диапазон и не передаёт
старый широкий/неочищенный контекст. Уже созданные карточки не удаляются.

Отчёты относятся к текущему проходу плюс ограниченному контексту, а не ко
всей истории. `context_complete`/числа coverage показывают пределы. Summary,
созвон, feedback и retro имеют проверяемые evidence refs и буквальные цитаты;
проверка ссылки не гарантирует правильность смыслового вывода модели.
При отсутствии материала отчёт пустой. Для отчётов Notion задаются собственные
страницы в `notion_reports`; обновляется только принадлежащий worker блок.

В свежем завершённом ответе необязательное предложение ответственного или срока,
которого нет в подтверждающих сообщениях, заменяется пустой строкой. Это не отменяет
проверку структуры, ключей, ссылок и буквальных цитат; задачи с непроверяемыми
ссылками или цитатами по-прежнему не принимаются. Проверка уже сохранённого
результата остаётся строгой.

Ключ задачи определяется anchor evidence + стабильным slot, не названием.
Входящие карточки получают предложенную начальную плановую дату при известном
горизонте, без превращения этой даты в дедлайн. После создания PATCH не содержит
ручных Статус/Ответственный/Плановая дата/Дедлайн. Предложения модели — отдельные
поля. Перенос в другую базу или страницу требует нового sync journal.

До создания карточки/блока intent сохраняется **в удалённый GitHub**.
При потере ответа поиск по ключу/маркеру может восстановить ID; пустой поиск
не разрешает повторный create. Нужна ручная сверка. Удаление старых задач
или истории не применяется. Сегодня/неделя/месяц пересчитываются по Europe/Moscow,
неделя с понедельника, только незавершённые карточки.

## Проверки

```sh
python3 -B -m unittest discover -s cloud -p 'test_*.py' -v
python3 -B cloud/qualify_cli.py
cargo test --locked -p tgsum-core --test cloud_package
bash scripts/check.sh
python3 scripts/desktop-e2e.py --cargo-run --report-dir /tmp/tgsum-cloud-ui
```

Все fixtures синтетические. Для реальной проверки отдельный manual dispatch
с `check_only: true` проверяет grant, формат/account/plan cache и writeback
без inference/задач. Сведения JWT являются проверкой согласованности, не
проверкой подписи; настоящий вызов Codex — отдельное доказательство.
Затем `check_only: false` проверяет анализ и Notion. Секреты не передаются в чат.
`qualify_cli.py` требует установленный Codex 0.155.1 и запускает ту же команду
с локальным синтетическим provider без входа: проверяет отсутствие tools и schema.
Точный стартовый notice о выключенном Code Mode допускается только до начала turn;
иные ошибки, незавершённый ответ и любые tool items отклоняются.

Rollback source — обычный `git revert` изменений ветки. До личной установки
сохраняются executable и app-data; новые истории не удаляются и не заменяются
старым backup. Отключение `enabled` останавливает удалённый worker без удаления
результатов. Точный личный backup/rollback command записывается при установке.
