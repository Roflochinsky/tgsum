# Обновляемый локальный пакет: MVP на Omarchy

Скоуп `tgsum-6gf.8`, 2026-10-02: пользователь самостоятельно выгружает выбранный
чат, TGSUM обновляет локальный пакет и при сохранённой настройке публикует его
в приватный GitHub. Telegram, его сессии и API приложение для этого не использует.
Квалификация относится к Linux/Omarchy x86_64; Windows/macOS в этот MVP не входят.

## Использование и контроль

В проекте включён ровно один Telegram-источник, выбран нужный период, режим
«только изменения» выключен. В карточке источника открыть «Обновляемый пакет
для ИИ», выбрать раздельные папки выгрузки и результата, сохранить настройки.
При первой настройке с прежним профилем `secrets` включается профиль Work
с автоматическим скрытием кандидатов; уже настроенный профиль сохраняется.
Сокращение ФИО в Office — отдельное правило, не обещание полной анонимизации.

«Обновить пакет» работает вручную. Флажок автообновления включает проверку
локальной папки каждые 30 секунд, пока TGSUM запущен. «Остановить» отменяет
работу и сохраняет паузу после перезапуска. Возобновление: включить флажок
и сохранить настройки. Изменение выбранного чата, периода или правил приватности
требует повторного сохранения настроек пакета.

Вход — `result.json` непосредственно в выбранной папке или в её подпапках
`ChatExport_*`. Выбирается самый новый JSON по времени изменения; ID должен
совпасть с сохранённым чатом. Неверный чат не подменяет выбранный источник.
JSON проверяется до EOF и дважды читается со сверкой байтов. Это проверка
доступных локальных файлов, а не сигнал завершения экспорта от Telegram.
Корректный, но сокращённый экспорт даёт сокращённый текущий пакет; отсутствующее
сообщение не считается удалённым из Telegram. Coverage остаётся unknown.

Готовая папка: `<output>/tgsum-<project-id>/current`. `README.md` содержит индекс;
`context-*.md` — обработанную переписку и evidence references; текстовые вложения
идут отдельными обработанными документами. `package.json` содержит список всех
файлов с размерами, SHA-256 и способом обработки. Дополнительные файлы связаны
с идентификаторами вложений из переписки. `manifest.json` описывает исходный
текстовый bundle; его отметки о невключённых бинарных файлах дополняет
`package.json`. Исходные имена бинарных файлов заменены на `file-NNNNN.ext`.

Контроль пользователя: статус последней попытки, дата последнего готового
пакета, число сообщений/файлов/пропусков/сокращений ФИО, папка результата,
GitHub-коммит либо ошибка публикации. При ошибке виден последний готовый пакет.
Публикация не означает, что ChatGPT уже прочитал репозиторий: подключение
получателя и его синхронизация — отдельный следующий этап.

## Файлы и ограничения

- PNG/JPG/JPEG/WEBP/GIF копируются побайтно, включая метаданные.
- DOCX/XLSX перепаковываются локально: русское `Фамилия Имя Отчество` заменяется
  на `Фамилия И. О.`. Поддерживаются разорванные Word runs, Excel shared/inline
  strings; форматирование и обычные формулы сохраняются. Правило не является
  универсальным распознавателем имён: иной порядок, регистр, язык, имя на картинке
  и неизвестное написание могут остаться. Другие персональные данные в Office
  этим правилом не скрываются. Макросы и встроенные исполняемые объекты отклоняются.
- Разрешённые UTF-8 текстовые вложения проходят существующие правила приватности.
- PDF, старые DOC/XLS, аудио, видео и архивы не публикуются; учитываются как пропуски.
- Отсутствующий файл с обычной ссылкой, несовпадение заявленного размера,
  изменяющийся файл или неисправный Office останавливают новую сборку. Явно
  недоступные ссылки самого Telegram-экспорта учитываются как пропуски.
- Лимиты: JSON 512 МиБ; 500 ссылок; бинарный вход 20 МиБ/файл; суммарный вход
  вложений и итоговый пакет 256 МиБ. Для текста также действуют 100 файлов,
  8 МиБ/файл, 32 МиБ исходного текста, 64 МиБ обработанного текста. OOXML:
  2048 ZIP entries, 64 МиБ распакованного содержимого, 16 МиБ на XML, глубина 256.
- Ссылки и пути не разыменовываются за пределы выбранного каталога; symlink,
  traversal, DTD, CDATA и неподдерживаемый OOXML отвергаются.

## Замена, хранение и GitHub

Новый пакет собирается отдельно, проверяется и становится `current` через
атомарную замену symlink. Прежние созданные поколения удаляются только при
подтверждённом владении и неизменённом manifest. Чужие/изменённые файлы,
исходники и другие проекты не удаляются. После аварии повторный refresh
восстанавливает работу; очистка повторяется. Это не secure erase носителя.
Приватные snapshots, mappings и старые reviewed bundles проекта сохраняются
для evidence; этот MVP очищает опубликованные поколения, не всю историю Project.

Непустое `owner/repository` включает GitHub-публикацию. Требуются установленные
`git`, `gh` и действующий вход `gh auth login`. Проверка приватности выполняется
до клонирования и перед push. Публикуются только проверенные файлы пакета в
`packages/<project-id>`, без приватного хранилища, исходного JSON и ключей mapping.
Git hook/global config отключены; токены обслуживает credential helper `gh`.
Повтор без изменений не создаёт коммит. Обычный push сохраняет чужие коммиты;
конфликт или потеря сети оставляют локальный результат и видимую ошибку,
автоматический следующий цикл повторяет попытку. Каждая команда ограничена 90 с.

Удаление старого файла обновляет текущую ветку, но не стирает историю Git.
Приватный репозиторий не равнозначен дополнительному шифрованию содержимого.
Автоматическое переписывание истории не выполняется. Обработка не запускает
облачный inference и обучение; GitHub — отдельно выбранное хранилище результата.
[Review метода и retention](../research/local-package-github-2026-10-02.md).

## Воспроизводимые проверки

```sh
bash scripts/check.sh quick
cargo test --locked -p tgsum-core --test local_package
cargo test --locked -p tgsum --lib package_github::tests
python scripts/desktop-e2e.py --cargo-run --report-dir /tmp/tgsum-mvp-e2e
cargo build --locked -p tgsum-core --example local_package_probe
python scripts/local-package-benchmark.py --report /tmp/tgsum-package-benchmark.json
cargo install --path src-tauri --debug --locked --root /tmp/tgsum-install-check
uv run --with websocket-client python scripts/local-package-install-smoke.py /tmp/tgsum-install-check
bash scripts/check.sh
```

Все fixtures синтетические. Git roundtrip использует локальный bare remote;
WebView запускает собственное приложение. Install smoke устанавливает обычную
сборку, обновляет её в том же изолированном prefix, проверяет launcher, состояние
проекта, приватность текста и сохранение паузы. Опубликованный релиз/подпись,
автоматическая выгрузка Telegram и другая ОС этим не квалифицируются.

Итоговая квалификация: полный `scripts/check.sh`, 18 реальных WebView-сценариев,
изолированные установка/обновление/перезапуск и локальный Git roundtrip прошли.

production backend в созданный приватный GitHub: private=true, remote commit
совпал с квитанцией, повтор не создал новый коммит. Это проверка output, без
обращения к Telegram. [Машинный отчёт синтетических проверок](evidence/local-package-2026-10-02.json).
