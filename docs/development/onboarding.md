# Проекты, последовательность действий и помощь

Актуальное поведение интерфейса, 2026-10-07 (`tgsum-uly`); исходная работа —
`tgsum-hzm.10`. Интерфейс использует существующие команды проектов, подготовки
файлов и анализа. Протоколы агентов и способы получения архивов не изменены.

## Последовательность действий

- Обычный запуск открывает выбор `result.json`, без обязательного знакомства
  и без создания проекта. Файл в аргументах открывает выбор чатов для разового
  экспорта. Разовый экспорт сохраняет Markdown в папку, указанную на шаге
  **Сохранение**.
- **Помощь** открывает три страницы по запросу: как сохранить переписку, как
  получить JSON в Telegram и как повторно обрабатывать архивы в проекте.
  Настройка ИИ находится в раскрываемом разделе на последней странице.
  Обнаруженный путь к программе ещё не подтверждает её совместимость.
- Помощь открывается поверх текущего экрана и не пересоздаёт формы. Её можно
  закрыть на любой странице; автоматически при следующем запуске она не открывается.
- **Проекты** открываются отдельной кнопкой. Создание не требует входа в аккаунты.
  Шаги проекта: **Источники → Проверка → Получатель → Запуск → Результаты**.
  Навигация показывает один раздел за раз. Выбор получателя доступен после
  подготовки файлов и разрешения находок, требующих решения.
- **Сохранить в папку без ИИ** выбран по умолчанию: файл входа и модель не нужны.
  Сохранение сразу открывает результат с точным путём и кнопкой открытия папки.
  Для Codex/Claude есть отдельная проверка получателя и кнопка **Начать анализ**.
  [Контракт запуска](desktop-analysis.md) сохраняется.
- **Собрать выбранные чаты в папку** принимает папку с `result.json` и вложениями
  либо её родительскую папку с `ChatExport_*`/`DataExport_*`. Результат создаётся
  в отдельной подпапке выбранной папки назначения; готовый путь показывается
  из `ready.directory`. Новые экспорты сохраняет сам пользователь. Автоматическое
  обновление пакета проверяет файлы, пока TGSUM открыт; оно не получает сообщения
  или уведомления из Telegram.

Ошибка валидации или подготовки не перерисовывает форму: даты, модель и другие
введённые значения остаются для исправления. Сохранение одного чата оставляет
несохранённые карточки других чатов, включая выбор вложений. Подготовка недоступна,
пока эти изменения не сохранены. При конфликте версий подготовленный запуск
отменяется; форму можно сверить и явно загрузить изменения. Эта кнопка
предупреждает о сбросе формы. Проверка версии на стороне Rust остаётся обязательной.
Ошибка открытия архива сбрасывает незавершённое подключение к проекту: следующий
разовый экспорт не добавляет в него чаты. При смене проекта прежний путь результата
и кнопка его открытия очищаются.

WebView хранит только `seen`, default agent ID и до 20 недавних Project IDs
в `tgsum.ui.v1`. Auth/source paths, tokens, сообщения и модель туда не записываются.
Повреждённая или недоступная UI storage не блокирует работу. Project store остаётся
источником содержимого/истории; UI preferences не являются execution capability.

## Воспроизводимая проверка

Linux/WebKitGTK, debug build, отдельный пустой XDG-профиль. Запустить приложение
в одном терминале; не использовать реальный Project store:

```sh
TGSUM_UI_TEST_DIR=$(mktemp -d /tmp/tgsum-ui.XXXXXX)
env XDG_DATA_HOME="$TGSUM_UI_TEST_DIR/data" \
    XDG_CONFIG_HOME="$TGSUM_UI_TEST_DIR/config" \
    XDG_CACHE_HOME="$TGSUM_UI_TEST_DIR/cache" \
    WEBKIT_INSPECTOR_HTTP_SERVER=127.0.0.1:9263 \
    TGSUM_ANALYSIS_FIXTURE=1 \
    cargo run -p tgsum --features analysis-fixtures
```

В другом терминале из корня репозитория:

```sh
PYTHONDONTWRITEBYTECODE=1 uv run --with websocket-client \
  python scripts/ui-onboarding-smoke.py 9263
```

Скрипт отказывается работать без тестового обработчика анализа или с непустым
хранилищем проектов. Это настоящее приложение Tauri: проверяются старт без
модального окна, открытие помощи, явный переход к проектам и создание через форму.
Команды приложения добавляют тестовый архив из репозитория; остальные шаги
выполняются через интерфейс. Проверяются сохранение ввода при ошибке дат,
повторная помощь, конфликт второго редактора, явная перезагрузка, выбор сообщений,
полнота истории, сохранение без ИИ и оба тестовых сценария анализа.
Системные диалоги выбора в этом скрипте обходят при подготовке тестовых данных.
Для повторного полного запуска нужен новый пустой профиль.

Общий [desktop E2E](desktop-e2e.md) дополнительно проверяет несколько несохранённых
карточек, неудачное подключение архива, смену проекта и готовые файлы пакета.
Он запускается отдельным процессом и пишет отчёт с версией исходников; конфигурация
CI сама по себе не означает, что проверка прошла. Исторические результаты и границы
проверки платформ приведены в его документации. Реальные аккаунты не используются.
