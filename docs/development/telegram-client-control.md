# Управление режимом штатного Telegram

Состояние 2026-10-08: Linux-модуль `src-tauri/src/telegram_client.rs`
подключён к worker и кнопкам запуска/остановки. Один контроллер обслуживает
все включённые управляемые источники. **Личная установка пока не обновлена;
реальный Telegram этим контроллером пока не перезапускался.**
Постоянный источник остаётся исследовательским; готовность
определяет [контракт](../specs/telegram-continuous-source.md), а не наличие модуля.
Beads: `tgsum-i1w.13`.

## Сохранённое разрешение и кнопки

Project schema 11 хранит `manage_client` отдельно от привязки журнала. Старые
планы, включая schema 10 без этого поля, остаются в ручном режиме; чтение не
переписывает их файлы. Новая форма предлагает автоматический режим. «Найти
Telegram» только определяет папку работающего клиента. Первый управляемый
запуск проверяет совпадение этой папки, отсутствие ссылок в пути и bootstrap
выбранного чата до сохранения настроек. Отсутствующая `DebugLogs` допустима
только внутри проверенного работающего профиля. Stop не добавляет разрешение;
смена режима включённого источника требует сначала остановить его.

Все включённые управляемые источники должны иметь одну папку логов и один
локальный account namespace. Остановка одного чата оставляет debug для остальных;
последний Stop или Disconnect восстанавливает исходный режим. При ошибке
восстановления источник уже остановлен, история сохранена, а повтор доступен
в карточке и в «Работа в фоне». Недоступный Project нельзя считать остановленным:
управление остаётся заблокированным до восстановления его настроек. Ручные планы
читают готовые логи и не дают разрешения менять режим Telegram.

Перед действием worker подтверждает сохранённый head: синхронизирует manifest,
каталоги revisions/Project/store и родитель store, затем проверяет revision ещё
раз. Видимость файла после ошибки публикации сама по себе не разрешает запуск.
Неопределённая ошибка Start закрывает writers и блокирует действия до явного
повтора или восстановления в новом процессе. Обычный CAS-конфликт или ошибочное
значение до публикации не останавливают другие сборщики.

Штатный Exit закрывает writers, восстанавливает клиент и освобождает блокировку
управления до освобождения single-instance. Завершённый runtime отклоняет
отложенные команды до изменения Project или отмены подготовленного анализа.
Сохранённые enabled планы возобновляются новым процессом TGSUM.

## Что делает контроллер

`Controller<Desktop>` получает существующий запуск, включает runtime `-debug`
штатным завершением и повторным запуском, затем `restore()` возвращает прежний
режим. Если `-debug` уже принадлежал пользователю, контроллер только использует
этот режим и не выключает его. Наличие отдельной persistent-настройки блокирует
управляемое переключение; её содержимое не читается и настройка не меняется.

`StockDesktop` принимает только Arch-пакет **7.2.5-1**, `/usr/bin/Telegram`, один
процесс текущего UID и известные параметры `-debug`, `-autostart`, `-startintray`,
`-workdir`. Другой пакет, несколько процессов, `-many`, URL, ключи и неизвестные
аргументы отклоняются. Это граница текущего адаптера, не обещание поддержки
других версий или ОС.

Сохраняются только параметры запуска: executable, фактическая working directory,
разрешённые параметры и идентичность процесса. Она включает PID, start ticks,
boot ID и device/inode executable. Рабочая папка явно закрепляется аргументом
`-workdir`, даже если его не было в исходном argv; прежний профиль и разрешённые
параметры сохраняются. Файлы сессии, cookies, память и `/proc/*/environ` не
читаются. Для `tdata/withdebug` проверяется только наличие через no-follow metadata.

## Завершение именно проверенного процесса

Обычный вторичный `Telegram -quit` адресует имя профиля, поэтому между проверкой
и командой его место мог бы занять другой процесс. Адаптер находит listening
abstract Unix socket среди дескрипторов проверенного PID, открывает одно
nonblocking соединение, проверяет `SO_PEERCRED` PID/UID и повторно проверяет
полную идентичность. Через удерживаемое соединение отправляется только штатная
команда `CMD:quit;`. Подмена имени сокета после connect не перенаправляет её.
После ошибки повторного подключения нет; принудительные сигналы пользователю
не отправляются. Выход самого процесса проверяется отдельно с timeout.

Команда и Unix endpoint закреплены по Desktop commit
[`2f41383` sandbox.cpp](https://github.com/telegramdesktop/tdesktop/blob/2f41383dddd338fe17fd4711afd02688c418fd47/Telegram/SourceFiles/core/sandbox.cpp),
а выбор фактической папки — по
[logs.cpp](https://github.com/telegramdesktop/tdesktop/blob/2f41383dddd338fe17fd4711afd02688c418fd47/Telegram/SourceFiles/logs.cpp).
Первичные исходники перечитаны 2026-10-08. Это внутренний протокол клиента;
новая версия требует отдельной проверки совместимости.

## Перезапуск и восстановление

Приватный append-only журнал управления сохраняет последовательность
`Prepared → DebugPending → Active → Restoring → RestorePending → Released`.
`Prepared` закрепляется до первой команды остановки. Новая идентичность
записывается после подтверждения debug-запуска. Удерживаемые directory/file
handles, private permissions, lock, no-clobber publication и fsync защищают
записи; неподтверждённая публикация останавливает дальнейшие действия этого
контроллера до повторного открытия и синхронизации receipt/marker/root/parent.

Новый журнал сначала строится в собственной брендированной staging directory,
затем публикуется через `rename NOREPLACE`. Поздно появившийся чужой целевой
каталог не получает marker и не перезаписывается. После ошибки брендированная
stage остаётся записью незавершённого создания. Автоматического удаления нет:
проверка inode перед pathname unlink не исключает подмену между этими действиями.
Неизвестные файлы или изменённый marker сохраняются. Журнал управления,
история наблюдений и диагностические логи не удаляются.

Перезапуск TGSUM может продолжить записанный управляемый процесс. Если Telegram
исчез, контроллер запускает его с сохранённым профилем. Процесс, запущенный до
сбоя, но ещё не получивший запись идентичности, автоматически не присваивается
и не завершается. Ошибка объясняет необходимость возврата к обычному запуску.
Если обычный запуск уже восстановлен, журнал освобождает управление без quit.
После записи `Released` сохранённое разрешение может возобновить сбор даже если
клиент затем закрыли: используются только ранее проверенный профиль и параметры.
Без такого журнала первый запуск требует существующего клиента.
Сам `Drop` не перезапускает пользовательский клиент.

Telegram запускается через отдельный transient user scope:
`systemd-run --user --scope --quiet --collect --no-ask-password
--expand-environment=no --unit=<unique>.scope -- <executable> <arguments>`.
Он получает графическое окружение запуска, но свой cgroup: остановка сервиса
TGSUM не должна завершать восстановленный обычный Telegram. Отключение expansion
сохраняет буквальный `$` в пути профиля. Поведение сверено с установленным
systemd **261.2** и
[его man source](https://github.com/systemd/systemd/blob/v261.2/man/systemd-run.xml).

## Проверка и оставшаяся работа

Focused suite использует искусственный `Desktop`, собственные private directories
и собственные abstract Unix sockets. Он проверяет переходы и crash recovery,
полную идентичность, foreign-path preservation, lock, FIFO/symlink refusal,
неоднозначную публикацию, ноль отправленных байтов при неверном peer и отсутствие
перенаправления команды на заменивший endpoint процесс.

[Отчёт первоначального модуля](evidence/telegram-client-control-2026-10-08.json) закрепляет
source hashes, 22 focused tests, full workspace gate и отдельный scoped verifier.
У verifier 22 штатных теста и две независимые проверки прошли; шесть mutations
дали RED и GREEN после возврата guards. Это qualification библиотеки и fixtures.

```sh
bash scripts/check.sh quick
cargo test -p tgsum --lib telegram_client --all-features --locked
bash scripts/check.sh
```

[Scope evidence](evidence/telegram-client-scope-2026-10-08.json) подтверждает
на настоящем user systemd собственного Arch одинаковый spawn/command PID,
отдельный cgroup, сохранённую cwd и literal UTF-8/`$` arguments. Удаление
`--expand-environment=no` ломает assertion; возврат исправления его восстанавливает.
[Исполненный probe](evidence/telegram-client-scope-probe-2026-10-08.py) запускает
только собственные Python-процессы. Units и временные profiles убраны.
Это не проверка жизненного цикла реального Telegram.

Runtime-интеграция использует искусственный Desktop в тестовом Tauri harness:
он записывает команды только в собственную временную папку и не обращается
к процессам, сокетам или аккаунтам Telegram. Это отделяет проверку UI и общего
контроллера от проверки настоящего клиента. [Отчёт интеграции](evidence/telegram-managed-runtime-2026-10-08.json)
закрепляет 45 focused tests, full gate, 28 проверок запущенного Tauri на Arch
и отдельный verifier. [Снимок UI](evidence/telegram-managed-client-ui-2026-10-08.png)
показывает успешное восстановление искусственного клиента. До полной готовности нужны обновление
личной установки с backup/rollback, её background/login/restart и контролируемое
новое сообщение VibeCoders. Реальные edit/delete проверяются отдельно.

В этой части изменён только исходный код и собственные fixtures. Для отмены
используется обычный `git revert` соответствующего commit. Личная установка,
пользовательские units и исходный режим Telegram не менялись, поэтому backup
пользовательского профиля для этого прохода не создавался.
