# Пробный локальный сбор сообщений Telegram

Это эксперимент для **штатного Telegram Desktop 7.2.5 на Arch Linux**, одного
аккаунта и одного чата. Это отдельная программа, а не новое подключение в
интерфейсе TGSUM. Она не вызывает Telegram API, не входит в аккаунт и не меняет
клиент. [Проверка способа подключения](../research/telegram-debug-logs-2026-10-08.md)
описывает источник, формат и ограничения.

## Что сохраняется

Программа читает новые записи в явно указанной папке `DebugLogs`. Из известных
входящих пакетов она выделяет текстовые сообщения выбранного native peer ID.
Результат — приватный `capture-state.json` в отдельной папке: события с точными
ID, версиями текста, доступным отправителем, временем, локальной привязкой аккаунта,
позициями чтения и признаками неполноты. Другие чаты и исходные пакеты не копируются
в результат. Логи Telegram при этом остаются общими для всего клиента.

Это ограниченный журнал эксперимента. Он не обновляет существующий проект TGSUM,
не скачивает вложения, не передаёт данные AI и не заменяет начальную историю из
JSON-экспорта. Событие из транспортного лога не доказывает, что Telegram принял его
как окончательное состояние. Режим отладки, ротация файлов, остановка клиента и
неизвестные пакеты могут создавать пропуски; программа не заявляет полноту.

Папка результата должна принадлежать только этому эксперименту. Проверка пути,
файла и блокировка защищают от случайного повторного запуска, но не гарантируют
сохранность при одновременной замене пути или записи в файл другой программой того
же пользователя. Для постоянного сбора эту границу хранения нужно усилить.

## Перед запуском

1. Подтвердить один аккаунт и native ID нужного чата из предоставленного экспорта
   или сохранённого проекта. Указать тип: `channel` для супергруппы/канала, `chat`
   для обычной группы, `user` для личной переписки. Имя чата не является ID.
2. Проверить установленную версию и фактическую папку данных Telegram. Для Arch
   используйте `pacman -Q telegram-desktop`. Значение `--client-version` — явное
   подтверждение оператора, а не автоматическая проверка binary.
3. Сохранить исходный способ запуска. Для простого обратного запуска ниже нужно
   заранее убедиться, что persistent debug setting не включён. Программа не читает
   базы сессий и не меняет эту настройку.
4. Подготовить приватную папку источника и выбрать **новую** папку результата вне
   Git-репозитория и вне источника. Общие MTP-логи могут содержать другие чаты и поля
   авторизации; не прикладывать их к AI, issue, CI или публичным отчётам.

## Запуск

Сначала собрать программу из корня репозитория:

```sh
cargo build --locked -p tgsum-core --bin telegram-debug-capture
```

Штатно завершить тот же Telegram и дождаться его закрытия; затем включить отладку
с прежним профилем. На этой машине executable — `/usr/bin/Telegram`. Запуск флага
при уже работающем экземпляре не включает отладку в нём.

```sh
/usr/bin/Telegram -quit
# Дождаться завершения Telegram; сохранить прежние profile/workdir options.
umask 077
/usr/bin/Telegram -debug
```

В другом терминале, заменив пути и пример ID своими значениями:

```sh
target/debug/telegram-debug-capture \
  --logs "$HOME/.local/share/TelegramDesktop/DebugLogs" \
  --output "$HOME/.local/share/tgsum-telegram-debug/trial-001" \
  --account primary --peer channel:123 \
  --client-version 7.2.5 --single-account-confirmed --seconds 60
```

Открыть выбранный чат обычным клиентом. Получение новых сообщений зависит от
событий Telegram; пустой результат не означает пустой чат. Программа выводит
только счётчики и технические признаки неполноты. Через заданные 1–300 секунд
чтение прекращается. Повторный запуск с той же привязкой и папкой продолжает
чтение; менять аккаунт, peer или источник в существующем журнале нельзя.

## Остановка и обратный запуск

Остановка сборщика **не выключает** отладку Telegram. После эксперимента штатно
завершить клиент и запустить исходную команду без `-debug`:

```sh
/usr/bin/Telegram -quit
# Дождаться завершения; восстановить прежние profile/workdir options.
/usr/bin/Telegram
```

Для stable binary с изначально отсутствующим persistent debug setting это
возвращает обычный режим. Проверить, что MTP-файлы больше не растут. Исходные логи
и выбранный журнал остаются приватно на диске: автоматического удаления нет.
Если прежний запуск отличался, восстановить именно его. При включённой persistent
настройке приведённая команда сама по себе отладку не выключает.

## Проверки

Synthetic fixtures и файловый симулятор входят в обычные Rust gates:

```sh
bash scripts/check.sh quick
cargo test --locked -p tgsum-core telegram_debug
bash scripts/check.sh
```

## Результат эксперимента 2026-10-08

На Arch Linux с установленным Telegram Desktop 7.2.5-1 пользователь подтвердил
один аккаунт и открыл выбранный чат. За 120 секунд клиент создал диагностические
логи; затем его штатно вернули в обычный режим. Проверены исходная команда запуска,
отсутствие постоянного включения отладки и прекращение роста MTP-файлов.

Первый проход не разобрал сообщения из-за формата signed HEX в типах вектора.
После исправления сборщик повторно прочитал уже созданные приватные логи:
сохранены **51 отдельное сообщение, 46 непустых текстов**; у всех 51 сообщений
есть ID отправителя (это не число разных авторов).
Все события принадлежат выбранному typed peer; текст всех 51 записей точно
соответствует строковому представлению в источнике, включая пустые строки.

Это сообщения из ответа истории при открытии чата (`observed`). Реальных новых
сообщений, правок и удалений в этом опыте не получено; их обработка, дописывание,
перезапуск и ротация проверены на искусственных данных. Полнота истории и
постоянный поток новых сообщений не подтверждены. В интерфейс TGSUM этот
эксперимент не встроен; connector остаётся `research`, без включённых операций.

Quick/full Rust gates, 28 тестов parser/capture и 2 теста CLI прошли. Изолированное
удаление исправлений escaping LF и signed vector tag делает соответствующие
регрессии красными. Отдельный проверяющий подтвердил финальные файлы parser,
capture и CLI. [Публичная запись результатов](evidence/telegram-debug-spike-2026-10-08.json)
содержит только версии, счётчики, хеши кода и ограничения. Исходные логи, native
IDs и журнал с текстами хранятся локально вне Git. Актуальные revision и результат
CI — в Beads `tgsum-i1w.12` для опубликованной проверенной ветки.
