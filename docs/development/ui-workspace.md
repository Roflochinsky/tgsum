# Рабочее пространство проектов

Актуальная навигация desktop UI, 2026-10-10. Изменения относятся к HTML/CSS и
клиентским контроллерам; Rust IPC, получение данных и границы отправки не меняются.

## Пользовательский путь

- Обычный запуск открывает **Мои проекты**. Помощь необязательна. Переданный
  приложению путь экспорта по-прежнему открывается для выбора чатов.
- Новый проект без источников открывает **Источники**. Сохранённый проект
  открывает последнюю доступную запись анализа; это чтение, а не новый запуск.
  Если чаты уже добавлены, но анализа ещё нет, **Сводка** показывает пустое
  состояние и действие перехода к проверке сообщений.
- В выбранной композиции «Сводка дня» сначала видны подтверждённый главный
  вывод, открытые вопросы, таблица следующих шагов, затем решения. Владельцы
  и сроки показываются только из сохранённых полей результата; неизвестные
  остаются «Не указан». Решения и открытые вопросы показываются при наличии
  соответствующего раздела recipe. Разные recipe не смешиваются в один анализ.
- Ссылки на сообщения и подтверждающие цитаты доступны в раскрываемых блоках.
  История анализов, сведения о запуске, периоды/темы и настройки защиты данных
  убраны с первого плана, но доступны. Статус покрытия остаётся рядом со сводкой.
- Верхняя навигация содержит **Сводка** и **Источники**. Меню с названием
  проекта содержит **Все проекты** и **Разовый экспорт**; дополнительное меню
  открывает историю, помощь и фоновую работу. **Все проекты** возвращает список. **Разовый экспорт** в верхней навигации
  открывает отдельный путь JSON → чаты → сохранение. Кнопка возврата из проекта
  не начинает импорт и не заменяет этот путь.
- Анализ сохраняет последовательность: проверка сообщений → выбор получателя →
  подготовка запуска → отдельное подтверждение. По умолчанию выбран экспорт
  без ИИ. Правка параметров аннулирует подготовленный запуск; нерешённые находки
  приватности блокируют отправку и экспорт. Ошибка или прерывание не запускает
  автоматический повтор.

## Синтетический просмотр настоящего интерфейса

```sh
python3 scripts/ui-preview-server.py --port 4187
```

Открыть `http://127.0.0.1:4187/`. Сервер отдаёт настоящие файлы `src-tauri/ui`,
добавляя mock `window.__TAURI__` только в HTTP-ответ. Производственные файлы не
патчатся и не импортируют mock. Превью отказывается заменять уже существующий
native bridge. CSP запрещает сетевые соединения, внешние скрипты, формы и фреймы.
Постоянная метка **Демо · синтетические данные** видна во всех сценариях.

Сценарии задаются query-параметром `scenario`:

- `ready` (по умолчанию): последний handover, отдельные summary и decisions, три действия,
  подтверждённые владельцы/сроки и действие без согласованного владельца/срока
- `empty`: нет проектов; можно проверить создание пустого проекта
- `no-analysis`: чаты есть, сохранённых анализов нет
- `failed`, `interrupted`, `uncommitted`: соответствующие состояния результата
- `privacy`: одна нерешённая находка, блокирующая дальнейший переход
- `export`: синтетический выбор `/demo/export/result.json`, папки `/demo/output`,
  прохождение разового экспорта и сохранение подготовленного Project bundle

В `export` экран завершения также синтетический: файлы не читаются и не
создаются. Открытие папки ничего не запускает. В остальных сценариях выбор
файла/папки возвращает отмену. Неизвестные операции отклоняются. Все изменения
живут только в памяти вкладки и сбрасываются при перезагрузке. Аккаунты,
авторизация, реальный Telegram и inference не используются.

Для существующего статического сервера можно материализовать отдельную папку:

```sh
python3 scripts/ui-preview-server.py --materialize /tmp/tgsum-preview
```

HTML копируется с mock и CSP; остальные активы ссылаются на текущие исходники.
Повторить команду после изменения `index.html`. Для замороженного снимка добавить
`--freeze`: активы и fixture копируются. Не размещать preview внутри
`src-tauri/ui` и не включать его в production-пакет.

## DOM-регрессии

Приложению не нужен npm build. `jsdom` нужен только для изолированного теста;
зависимость устанавливается вне репозитория, без install-скриптов:

```sh
npm install --prefix /tmp/tgsum-ui-contracts --cache /tmp/tgsum-npm-cache \
  --no-audit --no-fund --ignore-scripts jsdom@26.1.0
NODE_PATH=/tmp/tgsum-ui-contracts/node_modules \
  node --experimental-vm-modules scripts/ui-contract-tests.mjs
```

Тест загружает настоящий HTML и ES-модули в jsdom. Проверяет уникальные ID и
ссылки контроллеров на существующие элементы, новый старт/возврат, чтение
последнего анализа без запуска, свёрнутые доказательства, пустые и ошибочные
состояния, сохранение черновиков и CAS-конфликт, privacy gate, аннулирование
Review, повторное нажатие Run, безопасный текст, оба пути экспорта и отмену
выбора файла/папки. Первый аргумент может указывать другой каталог UI для
регрессионного сравнения. Старый UI должен провалить проверку project-first
старта; это ожидаемая отрицательная проверка.

## Нативная проверка обязательна отдельно

DOM-тест и browser preview не проверяют Tauri/WebKit, нативные диалоги, Rust
IPC, реальное чтение/запись файлов, системные интеграции и работу агента.
Дополнительно нужны ручной `cargo run -p tgsum` и
[изолированный desktop E2E](desktop-e2e.md):

```sh
cargo build --locked -p tgsum --features desktop-e2e
python3 scripts/desktop-e2e.py
bash scripts/check.sh quick
bash scripts/check.sh
```

Скрипты `ui-onboarding-smoke.py`, `ui-privacy-smoke.py` и
`ui-assisted-smoke.py` используют только явно запущенный изолированный
analysis-fixtures host, по инструкции в их заголовках. Их ожидания навигации
обновлены; проверка синтаксиса не означает прохождения native flow.

В среде проверки 2026-10-10 установлен закреплённый Rust/Cargo 1.98.1 и
подготовлены официальные Debian-зависимости GTK/WebKit в отдельном sysroot.
Проверки форматирования, workspace check и строгий Clippy прошли; нативный
Linux ELF-бинарник собран. Core-проверка: 343 passed. Полный workspace test
не прошёл: 2 desktop-теста и 10 runner-тестов требуют Unix-сокеты, запрещённые
средой (`PermissionDenied: Operation not permitted`). Диагностический прогон
остальных целей дал 485 passed, 10 failed, 28 штатно ignored; два уже
заблокированных desktop-теста были явно пропущены. Это не общий PASS.

Запуск GUI через D-Bus/Xvfb также блокируется запретом локальных сокетов;
защита не отключалась. Поэтому native UI, диалоги ОС и end-to-end IPC здесь
не подтверждены. `bd prime` и `bd list --status in_progress` недоступны
(`bd: command not found`), сохранение прогресса в Beads не заявляется.

## Источник композиции и активы

Выбранный пользователем вариант 2: спокойная сводка на одной странице, без
постоянного сайдбара. Заголовок берётся из первого сохранённого claim раздела
`overview` или `context`; числа выводятся из текущего результата. Период, статус
задачи, автор/время решения не выдумываются: `AnalysisView` этих полей не отдаёт.
Пустой owner означает «Не указан», а не доказанное отсутствие назначения.
Доказательства раскрываются локально: это не фиктивные ссылки Telegram.

Шрифт Onest уже поставляется с приложением. Иконки выбранной поверхности —
[Bootstrap Icons 1.13.1](https://github.com/twbs/icons/tree/v1.13.1), MIT;
исходники и лицензия в `src-tauri/ui/icons/`. `bootstrap.svg` — sprite,
составленный из неизменённых path официальных SVG, без нового runtime dependency.
Вкладки и клавиатурные действия мгновенны. CTA получает только pointer press
scale 0.96 / 150ms ease-out, отключённый при reduced motion.
