# GPT-6 Sol: исследование инструкций для агента

Дата проверки: **2026-09-26**. Целевая модель: **`gpt-6-sol`**.
Задача: собрать основания для настройки работы агента в tgsum до изменения
`AGENTS.md` и выбора памяти проекта. Ниже отдельно указаны факты о Sol,
рекомендации OpenAI с иной областью применимости и предложения для проекта.

## Что подтверждено именно для Sol

OpenAI описывает GPT-6 Sol как модель для сложного программирования и агентных
процессов. Карточка API указывает `reasoning.effort`: `none`, `low`, `medium`
(значение по умолчанию), `high`, `xhigh`, `max`. Для рассуждения с инструментами
нужен Responses API; function calling в Chat Completions поддерживается только
при `none`. Это характеристики API, а доступные настройки конкретного клиента
Codex нужно проверять отдельно. [Карточка GPT-6 Sol](https://developers.openai.com/api/docs/models/gpt-6-sol).

Актуальные best practices Codex прямо рекомендуют начинать с **Medium для
GPT-6 Sol**, затем менять уровень по задаче и результату.
[Codex: Context and prompts](https://learn.chatgpt.com/guides/best-practices#strong-first-use-context-and-prompts).

**Вывод для проекта:** сохранять выбранный `gpt-6-sol`; `medium` — обоснованная
отправная точка. Проверять более высокий effort на сложных задачах имеет смысл
сравнением результата и затрат. Оптимальный режим именно для tgsum ещё не измерен.

## Рекомендации семейства GPT-6 и их границы

Официальный guide предлагает начальные промпты для семейства GPT-6, но прямо
говорит: описанное поведение наблюдалось у **Astra**, а применимость необходимо
проверять на выбранной модели и своих задачах. Поэтому это кандидаты для Sol,
а не доказанные особенности Sol. [GPT-6: Prompting best practices](https://developers.openai.com/api/docs/guides/latest-model#prompting-best-practices).

В пределах этой оговорки полезны следующие рекомендации:

- **Самостоятельность:** явно поручать довести запрос до результата; уже
  разрешённые обратимые действия не должны требовать повторного согласования.
- **Уточнения:** задавать уровень самостоятельности; до запроса окончательного
  одобрения готовить результат, который пользователь сможет проверить.
- **Конфликты:** проверять доступные skills и инструкции; явно учитывать
  приоритет запроса пользователя над рекомендациями skill. Если skill вызвал
  остановку, показывать конкретную инструкцию и её источник.
- **Делегирование:** определять, когда и сколько работы передавать другим
  агентам, с учётом возможностей среды.
- **Проверки:** выполнять обязательные проверки; расширять или повторять их
  после успеха только при новых изменениях, ошибках или оставшейся неопределённости.
- **Ответы:** задавать желаемую краткость и понятный технический язык.

## Как формулировать конкретную задачу

Общий guide для reasoning models рекомендует короткие прямые инструкции,
явные ограничения и критерии успешного результата. Требование раскрыть
пошаговые рассуждения не нужно; примеры стоит добавлять при необходимости и
согласовывать с инструкциями. Этот материал содержит примеры o-series и не
является специальным исследованием Sol. [Reasoning best practices](https://developers.openai.com/api/docs/guides/reasoning-best-practices#how-to-prompt-reasoning-models-effectively).

Codex best practices предлагают четыре составляющие запроса: цель, контекст,
ограничения и критерий готовности.
[Codex: Context and prompts](https://learn.chatgpt.com/guides/best-practices#strong-first-use-context-and-prompts).

**Предлагаемый шаблон для tgsum** — наша адаптация этих составляющих и описанной
выше самостоятельности; её ещё следует проверить на реальной задаче:

```text
Результат: <наблюдаемое изменение для пользователя>.
Контекст: <issue, воспроизведение, затронутый сценарий>.
Ограничения: <совместимость и границы задачи>.
Готово, когда: <проверяемые условия и обязательные проверки>.
Продолжай до выполнения этих условий. Обычные локальные решения принимай
самостоятельно. Если без моего решения результат может существенно
измениться, задай конкретный вопрос и продолжай независимую работу.
В конце покажи результат, выполненные проверки и оставшиеся ограничения.
```

Общие правила поведения и сведения о конкретной задаче полезно хранить
раздельно: OpenAI рекомендует помещать общую роль/тон в инструкции, а детали
задачи и примеры — в пользовательский запрос. [Prompting: Refine your prompt](https://developers.openai.com/api/docs/guides/prompting#refine-your-prompt).

## Что взять из Codex Prompting Guide

Открытый guide от 2026-02-25 относится к **`gpt-5.3-codex`**; starter prompt
вырос из GPT-5.1-Codex-Max. В нём есть полезные инженерные приёмы: искать
существующие решения, пользоваться `rg`, объединять независимые чтения,
сохранять пользовательские изменения, проверять типы и ошибки, завершать
реализацию с проверкой. Применимость этих приёмов к Sol — инженерное
предположение. [Codex Prompting Guide](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide).

Guide требует осторожного чтения: начальный совет убрать промежуточные
сообщения уточняется ниже — для GPT-5.3-Codex и новее ими можно управлять
промптом. Поэтому перенос всего старого starter prompt может добавить
ненужные или противоречивые указания. [Codex: Mid-Rollout User Updates](https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide#mid-rollout-user-updates).

**Предложение для tgsum:** в `AGENTS.md` закрепить только местные правила,
пути к актуальным источникам и команды проверки. Существующий цикл
`bash scripts/check.sh quick` после Rust-правки, focused tests и полный
`bash scripts/check.sh` перед сдачей должен сохраняться. Полезность
инструкции определять тем, предотвращает ли она конкретную ошибку агента.

## Как проверить, что инструкции помогают

OpenAI рекомендует оценивать поведение на репрезентативных задачах, заранее
определять критерии и сравнивать результаты итераций. Из-за вариативности
модели одного удачного ответа недостаточно; автоматические оценки следует
сверять с человеческим суждением. Здесь применим метод оценки, без требования
внедрять сервис Evals. [Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices#design-your-eval-process).

**Предлагаемый набор для следующего этапа настройки** — проектный эксперимент,
который в рамках этого исследования ещё не запускался:

| Задача | Наблюдаемое доказательство |
| --- | --- |
| Небольшой Rust-баг | Воспроизведение, исправление, регрессионный тест, успешный полный gate |
| Правка документации | Проверенные факты и ссылки, уместный объём команд |
| Неоднозначное требование | Конкретное уточнение существенного решения, продвижение независимой части |
| Возобновление длинной задачи | Восстановлены цель, принятые решения, незавершённая работа и актуальное состояние |

Для сравнения фиксировать одинаковую исходную ревизию, запрос, модель,
effort и доступные инструменты. Смотреть на выполненные критерии, корректность
изменений, ненужные остановки, время и расход токенов, если доступен.
Внести одно изменение инструкции и повторить сравнение. Настройку считать
обоснованной после наблюдаемого улучшения на нужных проекту сценариях.

## `/goal`, инструкции и восстановление контекста

Goal хранится в состоянии конкретного треда: он задаёт результат, доказательства
готовности и ограничения. Это не общая память проекта. Для длительной задачи
нужно сохранять прогресс вне переписки; завершение требует проверки фактов,
а исчерпание бюджета не доказывает готовность. [Using Goals in Codex](https://developers.openai.com/cookbook/examples/codex/using_goals_in_codex).

Наш пример для tgsum (шаблон, задача сейчас не запускается):

```text
/goal Исправь потерю сообщений при разбиении экспорта на Markdown-файлы.
Сохрани порядок сообщений, UTF-8 и формат заголовков. Докажи исправление
регрессионным тестом, который падает до правки; выполни bash scripts/check.sh.
Храни воспроизведение, решения, результаты проверок и следующий шаг в задаче
Beads. Готово, когда все требования подтверждены на итоговой версии кода.
При блокере укажи точную причину и нужный вход; продолжай независимую работу.
```

Codex читает глобальные инструкции из своего home, затем проектные — от корня
репозитория до рабочей папки. Более близкий файл уточняет предыдущие; инструкция
загружается при старте сеанса. Поэтому правило Beads должно быть в корневом
`AGENTS.md` самого tgsum. Файл `~/AGENTS.md` нельзя считать переносимой настройкой
для всех клиентов. [AGENTS.md discovery](https://learn.chatgpt.com/docs/agent-configuration/agents-md#how-codex-discovers-guidance).

## Где хранить память проекта

В эксперименте OpenAI с длительной работой Codex использовались сохранённые
спецификация, этапы с проверками, решения и текущий статус. Это пример устройства
рабочего процесса; он не предписывает конкретный трекер. [Long-horizon tasks](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex#the-key-idea-durable-project-memory).

У Codex также есть локальная память: она может обновляться фоново и с задержкой.
OpenAI рекомендует хранить обязательные командные правила в `AGENTS.md` или
версионируемой документации. Поэтому автоматическое вспоминание не стоит делать
единственным способом восстановления работы. [Memories](https://learn.chatgpt.com/docs/customization/memories).

**Решение для tgsum:** продолжить существующий Beads. Это наш выбор для проекта,
а не рекомендация OpenAI использовать Beads. Роли источников:

| Источник | Что в нём хранить |
| --- | --- |
| `AGENTS.md` | Короткий порядок работы, ограничения проекта, условия готовности |
| Задача Beads | Критерии, зависимости, воспроизведение, результаты, следующий шаг |
| `bd remember --key …` | Проверенные долговечные выводы с указателем на источник |
| `docs/specs/`, `docs/research/` | Спецификации, основания решений, исследования со ссылками |
| `/goal` | Текущая цель треда и её жизненный цикл |
| GitHub Issues | Внешние обращения, если они используются; ссылаться на них из Beads |

Статусы не нужно независимо вести сразу в Beads и GitHub Issues. Переход на другой
трекер был бы отдельным решением с переносом существующей истории. Указанная
схема сохраняет текущий трекер и делает источники памяти явными.

## Проверка на этой машине

Ниже локальные наблюдения на 2026-09-26, а не обещание для каждого окружения:

- `codex --version`: **0.155.1**. Обновлённый `codex debug models` содержит
  `gpt-6-sol`, default `medium`, уровни `low`, `medium`, `high`, `xhigh`, `max`,
  `ultra`. Встроенный каталог `--bundled` его не содержал; это не означало
  отсутствия модели в актуальном каталоге. Значения CLI отличаются от API.
- В пользовательском `~/.codex/config.toml` выбраны Astra и `xhigh`.
  `AGENTS.md` сам по себе модель не переключает. Флаги CLI и проектный
  `.codex/config.toml` управляют выбором модели отдельно от инструкций.
  [Config basics](https://learn.chatgpt.com/docs/config-file/config-basic#configuration-precedence).
- До этой настройки `codex -m gpt-6-sol debug prompt-input` включал проектный
  раздел `Development feedback`, но не правило Beads из `~/AGENTS.md`.
- Beads существовал: задача `tgsum-61r` была закрыта с доказательствами проверок.
  `bd memories` возвращал пустой список. В старых notes оставалось «CI pending»,
  хотя `close_reason` уже содержал успех CI; notes исправлены по фактическому результату.
- `bd dolt remote list` указывал GitHub-репозиторий, но на момент аудита
  `git ls-remote origin 'refs/dolt/*'` не возвращал refs. Обычный push кода
  сам по себе не подтверждал сохранение базы Beads на другом компьютере.
- Синтаксис памяти и синхронизации проверен по локальным `bd remember --help`,
  `bd memories --help`, `bd dolt commit --help`, `bd dolt push --help`,
  `bd init --help`. Записи памяти включаются в `bd prime`.

Для отдельного запуска SOL с рекомендованным исходным effort, не меняя глобальные настройки:

```bash
codex -m gpt-6-sol -c 'model_reasoning_effort="medium"'
```

Исследование подтверждает источники и обосновывает устройство инструкций.
Проверка загрузки `AGENTS.md` и сохранения памяти подтверждает механизмы;
сравнительный прогон рабочих задач на SOL нужен отдельно, прежде чем обещать
измеримое улучшение качества или расхода токенов.

## Что применено и проверено после исследования

- Корневой `AGENTS.md` теперь описывает восстановление Beads, обновление решений
  и результатов, критерии завершения `/goal`, проверки по типу изменения и handoff.
  Его размер — около 5 КБ. Модель и effort в клиенте не менялись.
- `codex -m gpt-6-sol debug prompt-input` подтвердил включение нового workflow,
  правил Beads, памяти, проверки критериев и ссылки на это исследование.
  Это проверка загрузки инструкций, без запуска задачи моделью.
- Созданы две постоянные записи Beads с указателями на проверенные источники;
  `bd prime` включает обе в стартовый контекст.
- `bd dolt push` завершился успешно, появился `refs/dolt/data`. В отдельном
  чистом клоне команда `bd init --remote git+https://github.com/Roflochinsky/tgsum.git`
  с флагами из README восстановила обе записи и задачу `tgsum-oxw`.
  `bd config get issue_prefix` в клоне подтвердил `tgsum`.
- README содержит проверенный способ восстановления базы после `git clone`.
  GitHub Issues не создавались и не заменяли Beads.
